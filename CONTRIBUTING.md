# Working on Open Mouthpiece

OpenSCAD builds the geometry (`scad/`); a React app (`src/`) runs OpenSCAD in the browser
(WebAssembly), with an editor, sliders and a 3D viewer. There is no server: designs live in the
browser, in downloaded .scad files, or in share links.

## Quick start

```
npm install
npm run dev            # the app (Vite, first free port from 5173); scad/ is served live
npm run dev:lan        # the same, reachable from phones/tablets on your network
npm run build          # the site -> dist/ (docs/HOSTING.md); npm run preview to try it
npm test               # unit tests (Vitest) for the app's pure logic, src/*.test.ts
npm run check          # regression check of every param file; -- --update to accept changes
npm run sweep          # robustness sweep over the parameter space (a few minutes)
npm run lint           # ESLint (TypeScript, React hooks); npm run typecheck for tsc alone
npm run format         # Prettier (src/, scripts/); format:check only reports
node scripts/sync_voice_files.mjs     # after changing parameters/descriptions in the base file
npm run docs:params    # docs/PARAMETERS.md and its pictures, from the base file (~1 min)
node scripts/glossary_diagram.mjs     # the labelled pictures in docs/GLOSSARY.md (from the alto)
node scripts/make_variants.mjs alto   # regenerate a voice's Flamma/Silva/Unda variant files
node scripts/bundle_scad.mjs scad/alto.scad -o alto_flat.scad   # one-file version for other tools
```

`check` and `sweep` need a recent OpenSCAD nightly (Manifold backend): set `OPENSCAD` to its
command-line program (on Windows `openscad.com`, for console output), or have `openscad` on the
PATH.

## Layout

```
scad/lib/mouthpiece_base.scad   the generator: all parameters (alto defaults) + all geometry
scad/{alto,tenor,baritone,soprano}.scad   voice files: include the base, then their own values
scad/variants/                  Flamma/Silva/Unda variants (generated by scripts/make_variants.mjs)
scad/art/                       example pictures for the top picture
scad/lib/fonts/                 lettering fonts (SIL OFL, licence files alongside)
src/                            the app (React + CodeMirror 6 + three.js); src/wasm/: OpenSCAD runner
scripts/                        check, sweep, sync, variants, bundle, static-site build helpers
test/baselines.json             regression baselines for npm run check
worker/index.js                 the site's only server code: anonymous usage + error reports
docs/PRINTING.md, GLOSSARY.md   for players (HOSTING.md: for hosting a copy)
docs/dev/                       developer notes: GEOMETRY.md (the generator), APP.md (the app)
```

Read `docs/dev/GEOMETRY.md` before changing the generator and `docs/dev/APP.md` before changing
`src/` or `vite.config.ts`.

## Testing

- `npm test`: unit tests for the app's logic (fast, no OpenSCAD needed; CI runs them).
- `npm run check`: every param file renders as one closed solid, matches its baseline, and its
  one-file bundle renders the same. Needs OpenSCAD.
- `npm run sweep`: every setting at its extremes plus random mixes; any failure is cut down to a
  small file in `scad/_sweep/`.
- For the app itself, try it in the browser (`npm run dev`; add `?fresh` to start with empty
  storage).

## Rules of the road

1. **Edit parameters and their descriptions in `scad/lib/mouthpiece_base.scad` only, then run
   `node scripts/sync_voice_files.mjs`**; it rewrites every param file's Customizer block, keeping
   each file's values. Then `npm run docs:params` (docs/PARAMETERS.md follows the base file).
2. **Run `npm run check` before and after geometry changes.** It fails on any change; after an
   *intended* change run `npm run check -- --update` and commit the new `test/baselines.json`.
   Run `npm run sweep` after changing clamps or adding parameters (new Customizer params are swept
   automatically).
3. **`.scad` files stay LF-only** (`.gitattributes` enforces it). With CRLF the app's Customizer
   mis-attaches descriptions and drops the sliders.
4. **A correct mouthpiece is genus 1** (one through-bore). Manifold prints `Genus:`: more than 1
   means stray holes, 0 usually a detached piece. Check it, not just "watertight".
5. **Geometry guarantees are by construction** (clamps in the generator), never by hoping two
   independently tuned curves don't cross. See "Guarantees" below.
6. **Third-party models:** measuring dimensions is fine; don't commit other people's meshes or
   geometry traced from them, and credit sources in README.md. No brand logos or trademarks.
7. Scripts that measure geometry need the **design frame**: render with
   `-D print_orientation=false`.

## Param files

- A param file does `include <lib/mouthpiece_base.scad>` **first**, then assigns its values.
  OpenSCAD uses a variable's last assignment everywhere; with the include first this is silent.
- The Customizer shows only parameters declared in the opened file, so each param file carries the
  base's whole annotated block (tabs, sliders, one-line descriptions) with its own values.
  `scripts/voice_file.mjs` builds that block.
- `bundle_scad.mjs` flattens a param file into one file; `npm run check` verifies it renders
  identically.
- Descriptions: one short plain-language line per parameter (the single comment line directly
  above it), **~80 characters at most**: what it does, with its unit and direction (+/-). No
  claims about tone or feel. Leave it out when the label already says everything.

## Coordinate convention

Design frame: Z = bore axis (z = 0 shank end, z = L tip), Y = up (y = 0 is the table plane, body
above), X = width (symmetric). `print_orientation = true` (default) stands the finished part on its
shank end face for printing: `rotate([-bore_tilt,0,0])` turns the end-face normal to +Z, and
`end_face_lift` puts the face on z = 0.

## Guarantees

The generator clamps, so no parameter set can break the model:

1. The tenon grows around the socket (`socket_weight`); the bore axis rises if the socket would
   come within `min_wall` of the table plane.
2. The socket stops before the throat transition and the window (`eff_shank_depth`), but it is the
   fit on the horn, so the window (to >= 15mm), the throat position and its narrowing give way
   first; the socket only shortens on very short bodies.
3. Every interior ring point keeps its wall at its own height (`interior_fit`, two passes):
   `min_wall` before the window; under the window 0.6 x `side_rail_width` beside the window-width
   part and the full `min_wall` for a chamber scooped out wider than the window.
4. The roof is capped one wall below the exterior and never pushed up by the floor; the floor gives
   way instead (min channel 1.2mm before the window, 0.3 in it).
5. The window stays inside the reed table minus the rails (`window_rail_limit`); the window cutter's
   upper corners stay 0.6mm inside the exterior.
6. The throat comes at least 1mm before the window (`eff_throat_z`; real mouthpieces come close to
   that, so don't raise the margin); the window starts >= max(0.3 L, 20mm) from the shank end.
7. The exterior underside is floored at -40 (the table solve heads to -infinity where the tip
   pinches the width to 0, which once left a detached sliver).
8. The cap (`part = cap`) clears the body, the reed and the ligature at every station, so it
   slides on from the tip: a running max of support functions, like the ligature's. Only the
   collar may squeeze (`cap_grip`); `npm run check` proves the rest empty (`cap_clash`). The ligature
   and the cap work with any reed (nominal 3mm for the band's taper fit; room for 4mm in the cap).

## Lessons learned

Geometry:

1. **Winding matters on modern OpenSCAD.** `ring_loft` winds faces clockwise seen from outside;
   Manifold turns a `difference()` with inside-out cutters into a solid block.
2. **No `hull()` lofting** for the main solids (twist/wing/tangency artifacts); use `ring_loft`.
3. **Clamp against the exterior's real cross-section at the relevant height**, not its widest point
   or a "highest possible" roof.
4. **Watch for mutual recursion** among interior functions; OpenSCAD reports it on an unrelated name.
5. **Blend into lines, not endpoints**; PCHIP tables are C1 by construction.
6. **Avoid coplanar faces between booleans**; better, build features into a loft.
7. **Pointwise clamps distort shapes**; prefer shape-level definitions (the window is a slot + arcs).
8. **Functions and modules can be used before they are defined; top-level variables cannot**: one
   read before its assignment is undef, silently. Define inputs above their users. Top-level
   variables are evaluated once, so share expensive lists through them (`AIR_RINGS`).
9. **Don't space ring points by arc length in general**: between the closely spaced tip rings it
   slides points sideways (sawtooth folds). It's used only on ridged tops.
10. **Profile before optimizing.** `-o x.csg` times evaluation alone; with Manifold, evaluation
    (interior rings) dominates, and every extra OpenSCAD run costs a full evaluation.
11. When a clamp looks wrong, append echo loops to a copy of the file, or view it in the app with a
    section cut.

App:

1. `App.tsx` returns "Loading…" early: every hook goes above that return.
2. Never `Math.max(...points)` over a mesh (~100k values overflow the stack); loop.
3. STLs written for three.js need real facet normals (STLLoader uses the file's; zeros = black).
4. A second dev server on another port (`npx vite --port 5180 --strictPort`) is a separate origin
   with fresh storage: good for testing without touching your own saved designs.
